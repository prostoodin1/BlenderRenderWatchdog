# Blender Render Watchdog 2.6.0

> Версия 2.6.0 делает LAN основным режимом без Tailscale: главные ПК находятся автоматически, новый worker вводит короткий код только один раз, а повторные подключения используют сохранённое доверие. Для подключения через интернет добавлен опциональный SSH-туннель.

![Blender Render Watchdog 2.6.0 — рендер](https://github.com/prostoodin1/BlenderRenderWatchdog/releases/download/v2.6.0/BlenderRenderWatchdog-2.6.0-Render.png)

![Blender Render Watchdog 2.6.0 — сеть](https://github.com/prostoodin1/BlenderRenderWatchdog/releases/download/v2.6.0/BlenderRenderWatchdog-2.6.0-Network.png)

> В версии 2.3.1 главный ПК после сетевого рендера проверяет все кадры и автоматически отправляет повреждённые кадры на повторный рендер.

> В версии 2.3 добавлены продолжение по недостающим кадрам, ручной сетевой диапазон, Samples и диапазон для каждого устройства, имя главного ПК и остановка сетевого рендера.

> В версии 2.2.2 список главного компьютера и всех подключённых устройств виден на каждом участнике рендера.

> В версии 2.2.1 фоновая проверка GPU больше не открывает окно терминала каждые 15 секунд.

> В версии 2.1.1 в **Settings → Interface** добавлен мгновенный выбор языка: English и Русский. Выбор сохраняется между запусками.

Windows-приложение для надёжного фонового рендера Blender. Watchdog продолжает анимацию после сбоя, управляет очередью проектов, распределяет кадры между компьютерами и показывает состояние рендера на телефоне.

## Что нового в 2.6.0

- LAN стал основным режимом и не требует установки сторонних сетевых программ;
- главный ПК можно показывать или скрывать в локальной сети;
- хозяин выбирает, нужен ли новым устройствам шестизначный одноразовый код;
- после первого подтверждения worker получает отдельный токен, сохраняет его и переподключается без повторного ввода кода;
- LAN-объявление содержит только имя, адрес и настройки подключения — секреты в UDP-поиск не попадают;
- Tailscale-интеграция заменена на штатный Windows OpenSSH с установкой клиента/сервера из интерфейса;
- код `BRW4` содержит параметры SSH-туннеля, а сам туннель запускается скрыто через ключ или `ssh-agent`.

## Что нового в 2.5.1

- новый режим **Internet via Tailscale**: главный ПК публикует свой приватный Tailscale-IP, поэтому worker-компьютеры могут находиться в разных домашних, мобильных или офисных сетях;
- встроены проверка состояния, кнопки установки официального Windows-клиента и запуска безопасного входа Tailscale;
- режим **Keep my code** использует пользовательский секрет, постоянный порт и стабильный Tailscale-IP; **Generate every start** создаёт новый код при каждом запуске;
- коды `BRW3` явно содержат тип соединения Tailscale, а локальные коды `BRW2` из старых версий продолжают работать;
- над списком устройств появился отдельный progress bar с количеством кадров и примерным оставшимся временем;
- worker отправляет heartbeat параллельно загрузке проекта, рендеру и отправке результата, поэтому долгий кадр больше не переводит устройство в статус Offline;
- LAN-режим сохранён для быстрой работы внутри одной локальной сети.

## Что нового в 2.1

- полностью скруглённая matte-glass дизайн-система вместо стандартных квадратных ttk-контролов;
- мягкие многослойные карточки с тенями, тонким бликом и подсветкой при наведении;
- pill-навигация с плавным горизонтальным переходом между разделами;
- анимированные тумблеры, hover/focus-состояния, ripple при клике и shimmer прогресса;
- обновлённая мобильная панель с матовым стеклом, крупными радиусами и адаптивными переходами;
- сохранённая Git-история: визуальная система, анимации и релиз оформлены отдельными коммитами.

## Возможности

- автоматический перезапуск Blender и продолжение со следующего готового кадра;
- безопасная пауза после текущего кадра;
- простой интерфейс с отдельными Queue, Network, Insights, Sandbox, Advanced и Logs;
- скрытие ручных полей, когда используются параметры из `.blend`;
- очередь проектов с сохранением, перестановкой, оценкой времени и режимом «короткие сначала»;
- повтор неудачных кадров и переход к следующему проекту после исчерпания попыток;
- рендер последовательности с последующей сборкой MP4, WebM, MKV или AVI через FFmpeg;
- прогноз времени и памяти до старта, который уточняется по истории проекта;
- список самых долгих кадров и история прошлых рендеров;
- Auto Fix для безопасного исправления типовых проблем;
- Render Sandbox: сравнение Draft, Balanced и Quality последовательно или параллельно;
- сетевой рендер до пяти компьютеров с кодом подключения и ручным диапазоном для каждого узла;
- автоматическая балансировка: свободный узел забирает следующий кадр, поэтому быстрый компьютер выполняет больше работы;
- hot-plug: новый сетевой узел сразу подключается к активному рендеру, локальные GPU также отслеживаются;
- мобильная адаптивная панель: прогресс, очередь, превью, пауза, остановка, уведомления и выключение после завершения;
- автоматическое обновление из GitHub Releases.

## Быстрый старт

Скачайте `BlenderRenderWatchdog.exe` из [последнего релиза](https://github.com/prostoodin1/BlenderRenderWatchdog/releases/latest). Дополнительная установка Python не требуется.

1. Выберите `blender.exe`, проект и папку кадров.
2. При необходимости откройте Insights и нажмите **Analyze scene**.
3. Нажмите **Start render** или добавьте проект в Queue.

Для телефона скачайте из того же релиза `BlenderRenderWatchdog-Android.apk`. На ПК откройте **Settings**, запустите **Mobile dashboard**, скопируйте **Android sync code** и добавьте его на вкладке «Устройства» телефона.

## Видео

В Advanced выберите `video` либо включите **Compose frames after render**. Watchdog сначала создаёт восстанавливаемую последовательность кадров, затем запускает FFmpeg. Такой порядок не теряет весь ролик при падении Blender.

FFmpeg должен быть доступен как `ffmpeg.exe` в `PATH`. Поддерживаются:

- MP4 (H.264);
- WebM (VP9);
- MKV (H.264);
- AVI (MJPEG).

## Сетевой рендер

Для локальной сети на всех render-компьютерах нужны только Blender и Blender Render Watchdog.

1. На главном компьютере выберите **Local network (LAN)**, включите **Show this main PC on the local network** и нажмите **Start controller**.
2. Выберите, должен ли главный ПК запрашивать одноразовый код у новых устройств.
3. На worker-компьютере откройте Network, выберите главный ПК в найденном списке и при необходимости введите показанный шестизначный код.
4. На главном компьютере нажмите **Start render**. Прогресс и ETA появятся над списком устройств.

При следующих запусках код больше не спрашивается: приложение хранит отдельное доверенное подключение для этого главного ПК. Полный код `BRW2` остаётся доступен как запасной способ подключения по адресу.

Для SSH выберите **SSH tunnel**. На главном ПК укажите доступный с worker-компьютера адрес SSH, порт и Windows-пользователя, затем установите OpenSSH Server кнопкой **Install OpenSSH**. На worker нужен OpenSSH Client и настроенный приватный ключ либо `ssh-agent`. Код `BRW4` переносит адрес туннеля и токен приложения, но никогда не содержит пароль. SSH-сервер должен быть доступен извне: обычно для этого нужен проброс TCP-порта на роутере или внешний SSH-сервер.

Контроллер передаёт исходный `.blend` без промежуточной упакованной копии и сохраняет его имя. Готовые кадры сразу записываются в папку **Frames folder**, выбранную на первой вкладке, а временный cache worker удаляется после завершения. Если проект использует внешние ассеты, заранее упакуйте их средствами Blender либо сделайте их доступными рабочим компьютерам. Неудачный кадр возвращается в очередь до трёх раз. Максимум — пять одновременно подключённых узлов.

Для ручного распределения выберите устройство в таблице и задайте диапазон. Пустой диапазон означает автоматическую балансировку.

Worker можно запустить и из командной строки:

```powershell
BlenderRenderWatchdog.exe --worker-code BRW2-... --blender "C:\Program Files\Blender Foundation\Blender\blender.exe"
```

## Мобильная панель

В Settings выберите, должны ли коды обновляться при каждом запуске или оставаться постоянными. В постоянном режиме можно задать собственный ключ; кнопка **New key** отзывает старый доступ.

Запустите Mobile dashboard и вставьте показанный код `BRWM1` в Android-приложение. Телефон сохраняет несколько компьютеров, позволяет переименовывать и удалять их, показывает прогресс, историю, подробные показатели и превью последнего кадра, а также отправляет паузу или остановку. В настройках телефона доступны три цветовые темы. Web-панель по приватной ссылке также остаётся доступна.

## Render Sandbox

Sandbox делает три тестовых рендера выбранного кадра:

- Draft — быстрый черновик;
- Balanced — средний пресет;
- Quality — текущие Samples и Resolution.

После теста Watchdog сравнивает время и quality proxy и рекомендует самый быстрый вариант, сохранивший не менее 75% лучшего показателя. Параллельный режим быстрее, но требует больше CPU/GPU-памяти.

## Auto Fix и прогноз

Insights проверяет Blender, `.blend`, диапазон кадров, папку вывода, доступность записи, GPU, FFmpeg, свободное место и потерянные внешние файлы. Одной кнопкой исправляются только безопасные пункты: создаётся папка вывода и включается GPU для Cycles. Потерянные ассеты не изменяются автоматически.

Первый прогноз использует разрешение, Samples, движок и размер проекта. После завершённых рендеров приоритет получает реальная история этого `.blend`, а Insights показывает самые долгие кадры.

## Запуск из исходников

Требуется Python 3.12+ с Tkinter. Runtime-зависимостей кроме стандартной библиотеки нет.

```powershell
python blender_render_watchdog.py
```

Тесты:

```powershell
python -m unittest discover -s tests -v
```

Сборка автономного EXE:

```powershell
.\build_exe.bat
```

## Данные и безопасность

Настройки, очередь и история хранятся в `%LOCALAPPDATA%\BlenderRenderWatchdog`; временный cache сетевого worker очищается автоматически. Сетевой controller и мобильная панель защищены случайными токенами. Короткий LAN-код действует один раз и обновляется после успешного подключения. Отключение требования к коду безопасно только в доверенной локальной сети; облачный relay не используется.

Roadmap и предыдущие upgrade logs находятся в [GitHub Issues](https://github.com/prostoodin1/BlenderRenderWatchdog/issues).
