> Версия 3.0.4 упрощает SSH-подключение до одной готовой ссылки и гарантирует непрерывный рендер всей назначенной пачки одним процессом Blender.

> В версии 2.3 добавлены продолжение по недостающим кадрам, ручной сетевой диапазон, Samples и диапазон для каждого устройства, имя главного ПК и остановка сетевого рендера.

> В версии 2.2.2 список главного компьютера и всех подключённых устройств виден на каждом участнике рендера.

> В версии 2.2.1 фоновая проверка GPU больше не открывает окно терминала каждые 15 секунд.

> В версии 2.1.1 в **Settings → Interface** добавлен мгновенный выбор языка: English и Русский. Выбор сохраняется между запусками.

Windows-приложение для надёжного фонового рендера Blender. Watchdog продолжает анимацию после сбоя, управляет очередью проектов, распределяет кадры между компьютерами и показывает состояние рендера на телефоне.

## Что нового в 3.0.4

- на Main PC появилась всегда видимая кнопка **Create ready SSH link**;
- ссылка уже содержит группу, адрес, пользователя, порт и отдельный ключ — worker не настраивает их вручную;
- на Worker оставлены два понятных поля: SSH invitation link и BRW/одноразовый LAN-код;
- при отсутствии OpenSSH Client приложение предлагает установить его автоматически;
- приватный ключ после импорта убирается из видимого поля и сохраняется отдельным защищённым файлом;
- пачка из 10, 20 или другого количества последовательных кадров выполняется одним запуском Blender без перезапуска между кадрами.

## Что нового в 3.0.3

- в карточке группы появились отдельные мини-вкладки **Main PC** и **Worker**;
- worker видит списком открытые LAN-группы и ранее запомненные SSH-группы, даже если они временно недоступны;
- главный ПК одной кнопкой создаёт SSH-ключ и готовое приглашение, а оба устройства запоминают маршрут и стабильный ID друг друга;
- после краткого обрыва worker автоматически переподключается и продолжает работу без нового устройства в списке;
- пачка рендерится непрерывно до `N из N`, после чего worker сразу получает следующие кадры;
- CPU/GPU, Cycles backend и размер пачки сохраняются для всего компьютера и больше не меняются при выборе проекта.

## Что нового в 3.0.1

## Что нового в 3.0.0

- один активный проект для настольного интерфейса, сетевого плана и мобильной панели; состояние очереди автоматически мигрирует в новый формат;

- открытые группы и группы с одноразовым кодом, а также запоминаемое доверенное подключение;

## Возможности

- автоматический перезапуск Blender и продолжение со следующего готового кадра;
- безопасная пауза после текущего кадра;
- единый рабочий экран с очередью, активным проектом, рендером, группой и устройствами;
- скрытие ручных полей, когда используются параметры из `.blend`;
- очередь проектов с единым активным проектом, защитой от дублей, сохранением, перестановкой и оценкой времени;
- повтор неудачных кадров и переход к следующему проекту после исчерпания попыток;
- рендер последовательности с последующей сборкой MP4, WebM, MKV или AVI через FFmpeg;
- прогноз времени и памяти до старта, который уточняется по истории проекта;
- список самых долгих кадров и история прошлых рендеров;
- Auto Fix для безопасного исправления типовых проблем;
- Render Sandbox: сравнение Draft, Balanced и Quality последовательно или параллельно;
- сетевой рендер до пяти компьютеров с кодом подключения и ручным диапазоном для каждого узла;
- пакетная балансировка: узел получает непрерывный блок кадров, а адаптивный режим учитывает его фактическую скорость;
- hot-plug: новый сетевой узел сразу подключается к активному рендеру, локальные GPU также отслеживаются;
- мобильная адаптивная панель: прогресс, очередь, превью, пауза, остановка, уведомления и выключение после завершения;
- автоматическое обновление из GitHub Releases.

## Быстрый старт

Скачайте `RenderW.dog.exe` из [последнего релиза](https://github.com/prostoodin1/RenderW.dog/releases/latest). Дополнительная установка Python не требуется.

1. В Workspace выберите `blender.exe`, проект и папку кадров — проект станет активным во всём приложении.
2. При необходимости откройте Insights и нажмите **Analyze scene**.
3. Нажмите **Start render**, **Render queue** или **Render on group**.

Для телефона скачайте из того же релиза `BlenderRenderWatchdog-Android.apk`. На ПК откройте **Settings**, запустите **Mobile dashboard**, скопируйте **Android sync code** и добавьте его на вкладке «Устройства» телефона.

## Видео

В Advanced выберите `video` либо включите **Compose frames after render**. Watchdog сначала создаёт восстанавливаемую последовательность кадров, затем запускает FFmpeg. Такой порядок не теряет весь ролик при падении Blender.

FFmpeg должен быть доступен как `ffmpeg.exe` в `PATH`. Поддерживаются:

- MP4 (H.264);
- WebM (VP9);
- MKV (H.264);
- AVI (MJPEG).

## Сетевой рендер

Для локальной сети на всех render-компьютерах нужны только Blender и RenderW.dog.

1. На главном компьютере создайте или выберите группу, включите **Visible on LAN** и нажмите **Start group**.
2. Выберите **Open group** либо **Code required**. Во втором режиме короткий код нужен только при первом подключении.
3. На worker-компьютере нажмите **Join group**, выберите найденную локальную группу и подключитесь без ссылки.
4. На главном компьютере нажмите **Render on group**. Текущий проект, блок кадров, прогресс и ETA будут одинаковыми у всех участников.

При следующих запусках код больше не спрашивается: приложение хранит отдельное доверенное подключение и стабильный ID устройства. Смена локального IP не создаёт новый компьютер в группе. Если главный ПК недоступен, доверенный участник может выбрать сохранённую группу и стать новым главным ПК.

Для SSH откройте **Подключение**, выберите **SSH-туннель** и укажите доступный с worker-компьютера адрес, порт и пользователя. На главном ПК нажмите **Создать и скопировать SSH-приглашение** и подтвердите системную настройку OpenSSH. Приложение создаст отдельный Ed25519-ключ группы, добавит его в разрешённые ключи и скопирует приглашение `brw://join/...`. На worker достаточно вставить эту ссылку: приватная часть будет извлечена в закрытый локальный файл автоматически. Локальное обнаружение продолжает работать одновременно с SSH. Для связи через интернет SSH-сервер всё равно должен быть доступен извне: обычно нужен проброс TCP-порта или внешний SSH-сервер.

Контроллер передаёт исходный `.blend` без промежуточной упакованной копии и сохраняет его имя. Готовые кадры сразу записываются в папку **Frames folder**, выбранную на первой вкладке, а временный cache worker удаляется после завершения. Если проект использует внешние ассеты, заранее упакуйте их средствами Blender либо сделайте их доступными рабочим компьютерам. Неудачный кадр возвращается в очередь до трёх раз. Максимум — пять одновременно подключённых узлов.

Для детальной настройки выберите устройство в таблице: доступны диапазон, Samples, CPU/GPU, конкретный Cycles backend и собственный размер блока. Пустой диапазон и размер означают автоматическую балансировку.

Worker можно запустить и из командной строки:

```powershell
RenderW.dog.exe --worker-code BRW2-... --blender "C:\Program Files\Blender Foundation\Blender\blender.exe"
```

## Мобильная панель

В Settings выберите, должны ли коды обновляться при каждом запуске или оставаться постоянными. В постоянном режиме можно задать собственный ключ; кнопка **New key** отзывает старый доступ.

Запустите Mobile dashboard и вставьте показанный код `BRWM1` в Android-приложение. Телефон сохраняет несколько компьютеров, позволяет переименовывать и удалять их, показывает прогресс, историю, подробные показатели и превью последнего кадра, а также отправляет паузу или остановку. В настройках телефона доступны три цветовые темы. Web-панель по приватной ссылке также остаётся доступна.

## Render Sandbox

Sandbox делает три тестовых рендера выбранного кадра:

- Draft — быстрый черновик;
- Balanced — средний пресет;
- Quality — текущие Samples и Resolution.

После теста Watchdog сравнивает время и quality proxy и рекомендует самый быстрый вариант, сохранивший не менее 75% лучшего показателя. Параллельный режим быстрее, но требует больше CPU/GPU-памяти.

## Auto Fix и прогноз

Insights проверяет Blender, `.blend`, диапазон кадров, папку вывода, доступность записи, GPU, FFmpeg, свободное место и потерянные внешние файлы. Одной кнопкой исправляются только безопасные пункты: создаётся папка вывода и включается GPU для Cycles. Потерянные ассеты не изменяются автоматически.

Первый прогноз использует разрешение, Samples, движок и размер проекта. После завершённых рендеров приоритет получает реальная история этого `.blend`, а Insights показывает самые долгие кадры.

## Запуск из исходников

Требуется Python 3.12+ с Tkinter. Runtime-зависимостей кроме стандартной библиотеки нет.

```powershell
python blender_render_watchdog.py
```

Тесты:

```powershell
python -m unittest discover -s tests -v
```

Сборка автономного EXE:

```powershell
.\build_exe.bat
```

## Данные и безопасность

Настройки, очередь, группы устройств и история хранятся в `%LOCALAPPDATA%\BlenderRenderWatchdog`; временный cache сетевого worker очищается автоматически. SSH-ключи находятся в подпапке `ssh` с ограниченными правами доступа, а приватная часть приглашения не записывается в обычный конфиг. Сетевой controller и мобильная панель защищены случайными токенами. Короткий LAN-код действует один раз и обновляется после успешного подключения. Открытая группа безопасна только в доверенной локальной сети; облачный relay не используется. SSH-приглашение является секретом доступа — передавайте его только доверенным устройствам.
